# Modeling

## Task

Binary classification target: `exploited_30d` (see `PLAN.md` for label).
PatchPilot does **not** ship a "beat EPSS from scratch" classifier for
v0.1 — see Strategy below.

## Strategy: EPSS-complement (locked for v0.1)

`[train].strategy = "epss_complement"` in `config/settings.toml` is the
only supported v0.1 training strategy. Instead of predicting an absolute
probability of exploitation, the LightGBM booster
(`patchpilot.models.lgbm.LgbmModel`, `task="regression"`) predicts a
**residual** on top of point-in-time EPSS:

```
residual_target = exploited_30d - f_epss_score        # trained on
probability      = clamp01(f_epss_score + residual)    # served
```

This is a deliberate product decision, not a fallback: EPSS is already a
strong, well-calibrated baseline, so PatchPilot's job is to *add* signal on
top of it rather than compete with it from a cold start. It also gives a
hard safety property — a CVE with a high EPSS score is never silently
scored near zero just because the challenger model has nothing useful to
say about it (unseen CVE, missing features, degraded deployment with no
model artifact). See `src/patchpilot/serve/scoring.py::score_cve_ids` for
the exact fallback chain (`blend -> EPSS -> 0.0`).

Hyperparameters are chosen per temporal-CV fold by a small sequential grid
search over `max_depth` / `num_leaves` / `min_data_in_leaf`, scored on the
**blended** validation AUC-PR (`clamp01(epss + residual)` vs the true
label), not on the raw residual's regression loss — the model is judged on
what it is actually used for.

Residual (regression-task) models are **not** run through the isotonic
calibrator used for classification tasks: calibration assumes a
probability-vs-binary-label fit, which does not apply to a signed residual
that gets added to EPSS by the caller.

## Baseline (comparison only)

EPSS daily score, exposed as a `predict_proba` adapter so it shares the
evaluation harness with the challenger. For a fair head-to-head, the
holdout EPSS baseline uses the exact point-in-time `f_epss_score` feature
column that training saw — not a live/current lookup against silver
(`patchpilot.models.baseline_epss.EpssBaseline.from_silver`), which can
disagree with the training-time snapshot for CVEs whose EPSS moved after
publication. `patchpilot.eval.compare_epss.write_report` and
`patchpilot.eval.ablations.run_ablations` both prefer the PIT column when
it is present in the holdout frame.

Features are assembled by `patchpilot.features.point_in_time.assemble_feature_frame`:

- Tabular CVSS / CWE / reference flags (no current KEV membership)
- Point-in-time EPSS score/percentile (snapshot on or before publication)
- Per-row temporal publication-density features
- Optional CWE graph popularity features (`[features].include_graph`)

## Anti-leakage rules

- Features computed at each CVE's `published_date` for training/eval
  (EPSS snapshot on or before publication; temporal/graph counts exclude future CVEs).
- Current KEV membership is **not** used as a model feature (label leakage).
- Live scoring uses current EPSS via `assemble_scoring_frame`.
- Embargo between train end and validation start ≥ `horizon_days` (30).
- Right-censored window: CVEs published in the last 30 days are excluded
  from both train and eval (their 30-day window is not complete).

## Ablations

See `docs/benchmarks/ABLATIONS.md` (generated by `make ablate` /
`patchpilot eval --ablate`). Four variants, all scored on the same rolling
holdout with the same point-in-time EPSS column:

- **EPSS-only baseline (PIT)** — `f_epss_score` alone, no model
- **Full LightGBM (label target)** — fresh classifier trained directly on
  `exploited_30d` with all features (including EPSS); a from-scratch
  challenger, *not* what is shipped
- **LightGBM no-EPSS features** — same, with `f_epss_*` columns dropped;
  shows whether non-EPSS signal exists at all
- **EPSS-complement (residual blend)** — the actually-shipped strategy:
  `clamp01(epss + residual)` using the persisted `latest.json` artifact

The ablations report includes a lift line
(`delta-AUC-PR = complement - EPSS-only`) so the "does the residual help"
question has a single honest number, not vibes.

## Honesty note

If the challenger underperforms EPSS on the rolling holdout, document that
clearly in `docs/benchmarks/REPORT.md`. Do not market “beats EPSS” without
evidence.
