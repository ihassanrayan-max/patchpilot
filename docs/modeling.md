# Modeling

## Task

Binary classification: predict `exploited_30d` (see `PLAN.md` for label).

## Baseline

EPSS daily score, exposed as a `predict_proba` adapter so it shares the
evaluation harness with the challenger.

## Challenger

LightGBM binary classifier (`patchpilot.models.lgbm.LgbmModel`), fit with
time-respecting cross-validation (`patchpilot.train.temporal_cv`) and
calibrated with isotonic regression on the held-out validation fold
(`patchpilot.train.calibration`).

Features are assembled by `patchpilot.features.point_in_time.assemble_feature_frame`:

- Tabular CVSS / CWE / reference flags (no current KEV membership)
- Point-in-time EPSS score/percentile (snapshot on or before publication)
- Per-row temporal publication-density features
- Optional CWE graph popularity features (`[features].include_graph`)

## Anti-leakage rules

- Features computed at each CVE's `published_date` for training/eval
  (EPSS snapshot on or before publication; temporal/graph counts exclude future CVEs).
- Current KEV membership is **not** used as a model feature (label leakage).
- Live scoring uses current EPSS via `assemble_scoring_frame`.
- Embargo between train end and validation start ≥ `horizon_days` (30).
- Right-censored window: CVEs published in the last 30 days are excluded
  from both train and eval (their 30-day window is not complete).

## Ablations

See `docs/benchmarks/ABLATIONS.md` (generated by `make ablate` /
`patchpilot eval --ablate`). Typical variants:

- **full** — default feature set
- **no_epss** — drop `f_epss_*` features
- **epss_only** — EPSS baseline scores only (no LightGBM)

## Honesty note

If the challenger underperforms EPSS on the rolling holdout, document that
clearly in `docs/benchmarks/REPORT.md`. Do not market “beats EPSS” without
evidence.
